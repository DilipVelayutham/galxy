What's Missing
Frontend: the AI Preview Panel component referenced throughout §12 (which needs the exact 429/limit_reached shape) is not in this zip at all — only backend/ exists. Given the branch name feat-m5-frontend2, this looks like a separate PR/submission still to come; worth confirming with the intern whether it's tracked elsewhere.
Direct unit tests for ai_cache_service.make_cache_key() and ai_rate_limit_service.check_rate_limit() — current tests only exercise them indirectly through mocked Flask routes.
Any logged record for status="rate_limited" (see Issue 4) — meaning the admin dashboard in Module 12 will show 0 rate-limited events even when the limit is actively blocking guests.
A cleanup/expiry job for old ai_generations documents, even though created_at is indexed 'for cleanup/expiry jobs' per §2 — no such job exists yet (may be intentionally out of scope for this ticket).
Strengths
Prompt builder implements all four §5 placeholder rules correctly and has dedicated, passing-by-inspection unit tests for each (label resolution, affects_ai_preview exclusion, injection sanitization, empty-placeholder cleanup).
Provider adapter (ai_provider_client.py) genuinely follows the 'swappable provider' requirement from §4 — a registry dict + one function per provider, so adding OpenAI/Stability later is a small diff, not a rewrite.
Clean separation of concerns matches the spec's folder structure almost exactly, including keeping category/prompt-template ownership with Module 2 (the PUT route is deliberately not implemented here, per §9's explicit note).
Consistently avoids leaking raw provider errors to the client (502/504 responses are generic; internal exception text stays in logs only), per §6 step 8.
Cache correctly keyed on category_id + sorted attributes (order-independent) and correctly bypassed whenever a free-text/custom_text attribute is present, per §7.
module4_client.py fails closed on validation-service errors/timeouts (blocks the request) — the safer default, and a useful contrast to the rate-limit service's fail-open bug (Issue 2).
Includes a working dev fallback (M4_VALIDATION_MODE=local) so Module 5 can be developed and tested before Module 4 exists — a thoughtful touch for parallel team workflows.
Seed script and 15 automated tests (prompt builder + Flask route integration, all external calls mocked) give a working, demonstrable slice out of the box.
README is explicit about exactly what was and wasn't built ('Backend 1, T1+T2'), which stub routes belong to a teammate, and where a Day-3 merge-conflict risk exists (splitting ai_routes.py) — good team hygiene.
Recommended Fixes to Reach ~100%
Swap pipeline order: check rate limit before cache lookup, per §6.
Fail closed on rate-limit DB errors: block the request (429 or 503) instead of silently allowing it through when the quota count query fails.
Log rate_limited generations: insert a lightweight ai_generations doc with status="rate_limited" so admin analytics aren't blind to blocked attempts.
Lock down CORS to the real frontend origin before this leaves local dev.
Deliver or link the frontend piece (AI Preview Panel) that this backend contract was designed for — right now Module 5 has no way to be exercised end-to-end by a real user.
Add the two missing unit-test files for cache and rate-limit services to close the test-coverage gap.
