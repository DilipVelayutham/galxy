2. Micro-Timeline & Daily Execution Cadence
Day 1 — Base Initialization & Shared Assets (Isolation Build)
AM Kickoff: Initialize local environments. Pull the unified dev branch from origin and establish your feature branch locally (Naveen → feat-m5-t1-core-prompt, Gokul → feat-m5-t3-rate-limiting, Sawthi → feat-m5-frontend1-aipreviewpanel, Mohammed → feat-m5-frontend2-aigenerationhistory).
Shared Utility Ingestion: Immediately pull down Module 1's auth decorators and Module 10's Cloudinary base helper (backend) or shared upload widget (frontend) as soon as they are pushed to dev. Do not write localized duplicates.
Seed Ingestion: Naveen and Gokul execute python seed_categories.py inside the backend folder to provide a persistent database fixture for testing custom properties. Sawthi and Mohammed pull the same fixture's mock API responses for local component development.
Day 2 — Feature Maturity & First Synchronization Loop
AM Synchronization (Mandatory): Sync with the project-wide development stream by running the exact merge checklist below before writing code.
Parallel Coding: Naveen builds T1 orchestration + T2 prompt/provider together since T1 calls T2 directly. Gokul builds T3 caching + T4 rate-limiting together since both are guard layers checked in the same order. Sawthi and Mohammed build against Naveen/Gokul's documented interface contracts (see the four role handoff docs), using mocked responses until the real endpoints land.
Focus heavily on individual test coverage using mock interfaces on all four branches.
Day 3 — Internal Integration & Feature Freeze
AM Synchronization: Perform the final scheduled merge from origin/dev to catch external schema drifts early.
PM Self-Integration Check: Merge all four branches into the parent module-5-ai-preview local branch. Test full end-to-end telemetry (Route → Rate Limit → Cache Check → Prompt Gen → Gemini Mock → Cloudinary Asset Pipeline → AIPreviewPanel render → AIGenerationHistory render).
Watch out: ai_routes.py is touched by both Naveen (POST /api/ai/generate-preview) and Gokul (GET history/admin routes). Agree on merge order in advance, or split into ai_routes.py + ai_history_routes.py registered under the same router, to avoid a Day 3 merge conflict.
21:00 Deadline: Freeze features. Push finalized parent branch to origin and flag readiness to the Project Head.
Day 4 — Global Integration Gate
Standby Protocol: All Module 5 developers must remain active to support the Project Head during sequential integration mapping. Module 5 merges 6th in order. Fix semantic bugs instantly if escalated.

4. Critical Integration Guardrails
Guardrail: Module 5 does NOT author category attribute schemas — owned by Module 2. The affects_ai_preview flag and all attribute labels are read-only inputs for both backend prompt-building (Naveen) and frontend tab logic (Sawthi).
Guardrail: Module 5 does NOT validate configurations manually — validation delegates entirely to Module 4's validate_attributes(). Naveen's pipeline calls it first, before rate-limit or cache checks.
Guardrail: Module 5 does NOT calculate financial pricing metrics — pricing estimates are pulled independently via Module 4.
Guardrail: Do NOT build PUT /api/admin/categories/:id/ai-prompt-template — that route belongs to Module 2, even though it is adjacent to Gokul's admin_ai_routes.py work.
Watch out: Frontend contracts are now first-class handoff artifacts: Sawthi depends on Naveen's response shape (output_image_url, from_cache, generation _id) and Gokul's 429 shape (limit_reached, limit_scope). Mohammed depends on Gokul's GET /api/ai/generations/:user_id shape. Confirm these field names in writing before Day 2 coding begins, since a mismatch here is now a cross-track (not just cross-branch) integration failure.
