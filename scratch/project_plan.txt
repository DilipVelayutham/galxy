1. Project Vision
Galxy is a custom lighting and craft studio led by Asil, producing neon name boards, quilling art, acrylic moonlight lamps, fridge magnets, storeboard signage, and other bespoke lighting and craft work. The current presence is Instagram-only (@galxy.in).
This project delivers a full e-commerce style website that lets customers browse pre-designed products, configure fully custom pieces attribute by attribute, preview their design using AI-generated imagery, and check out — without an online payment gateway. Every order is confirmed manually by Asil offline, but the customer can track the live status of their order from placement through delivery.
The platform is built around one core engineering decision: every product category has a completely different set of configurable options — a neon board has font, color, chain, layer cut, and shape cut; a quilling piece has frame size, base color, and flower density. Rather than hardcoding each category, the system uses a schema-driven configurator engine that Asil fully controls from the admin dashboard — new categories and new options can be added with zero code changes.
1.1 Goals
Replace the Instagram-only presence with a full, dynamic, always-updatable website.
Give Asil a CMS where he controls every category, product, and configurable attribute without needing a developer.
Let customers visually approximate their custom design before ordering, using AI image generation.
Provide a full e-commerce style shopping experience — browse, cart, wishlist, checkout — without payment processing.
Give customers transparent, real-time order status tracking, updated directly by Asil.
Deliver a distinctive dark, neon-glow visual identity across the entire site that mirrors the products themselves.

6. Order Status Lifecycle
Every order moves through a fixed sequence of stages. Each transition is admin-authored, timestamped, and optionally carries a note visible to the customer. The customer sees this as a vertical progress tracker, similar to a courier tracking interface.
Stage
Meaning
Received
Order/inquiry submitted by customer, awaiting review.
Reviewed
Asil has reviewed the request and configuration.
Quote Sent
Final price communicated to customer (may differ from estimate).
Confirmed
Customer has agreed to proceed.
In Production
Piece is being made.
Ready
Production complete, awaiting dispatch/pickup.
Out for Delivery
In transit to customer.
Delivered
Order complete.
Cancelled
Can occur from any stage.

8. UI / UX & Design System — Dark Neon Identity
The website's visual identity is built to mirror the product itself: glowing signage in a dark space. Every screen — storefront and admin alike — uses a near-black base with neon-gradient accents, soft glow effects, and smooth, deliberate motion. This is a strict design language interns must follow, not a loose suggestion.
8.1 Color System
■  Background — Void Black  —  #0B0B0F
■  Surface — Panel Charcoal  —  #16161C
■  Primary Neon — Pink/Magenta  —  #FF2E8A
■  Secondary Neon — Electric Blue  —  #18E7FF
■  Accent Neon — Violet  —  #9B5CFF
■  Accent Neon — Signal Yellow  —  #FFD84D
■  Text Primary  —  #F4F4F7
■  Text Muted  —  #8A8A97
Every category can optionally be tagged with one accent neon color from this set (e.g. Neon Boards = Blue, Moonlight = Violet, Quilling = Pink) so each category page feels distinct while staying inside the same system.
8.2 Typography
Display/Headings: a bold, slightly rounded sans-serif (e.g. Clash Display, Poppins, or Space Grotesk) — large, confident sizing for hero and category titles.
Body: a clean, highly legible sans-serif (e.g. Inter or General Sans) at a comfortable size for product descriptions and admin tables.
Accent/Script: a script or handwriting font reserved for product-name previews on Quilling/Neon configurator text, echoing the product's own lettering style.
Headings and key CTAs may use a subtle text-shadow glow in the active neon color; body text stays clean and glow-free for readability.
8.3 Neon Glow & Surface Effects
Glow shadows: interactive elements (buttons, active nav links, selected configurator options, focused inputs) use a layered box-shadow glow in the element's accent color — soft, not harsh, tuned per component size.
Gradient borders: cards and panels use a 1px gradient border (pink → blue → violet) on hover or active state, rather than a flat border color.
Glassmorphism panels: modals, cart drawer, and configurator side-panel use a translucent dark background with backdrop blur, so content behind subtly shows through.
Grain/noise overlay: a very subtle animated noise texture over the dark background on the homepage hero, to avoid a flat, dead black.
Product photography treatment: product images sit on near-black backgrounds with a soft colored glow beneath them (matching the product's dominant neon color) to make every photo feel consistent with the brand even before any design work is applied.
8.4 Motion & Micro-interactions
Motion is a core brand element here — the site should feel alive the way a lit sign feels alive. All animation should use smooth, natural easing (ease-out for entrances, ease-in-out for state changes) and never feel abrupt.
Page transitions: soft fade + slight upward slide (200–300ms) between route changes.
Neon flicker-on: hero title and key headings animate in with a brief, tasteful "power-on flicker" effect on first load only — subtle, used once, never repeated on scroll to avoid annoyance.
Scroll reveals: sections and product cards fade/slide into view on scroll with staggered timing for grids (each card a few milliseconds after the previous).
Hover states: product cards lift slightly (translateY) and their glow intensifies on hover; buttons scale subtly (1.0 → 1.03) with the glow expanding outward.
Configurator feedback: selecting an attribute (color, font, chain, etc.) triggers a quick glow-pulse on the selected swatch/option and the price updates with a smooth count-up animation rather than an instant jump.
AI preview loading: while an image generates, show an animated glowing scan-line or pulsing gradient placeholder rather than a plain spinner, reinforcing the site's light-based theme.
Cart/wishlist actions: adding an item triggers a small icon bounce + glow flash on the cart/wishlist icon in the nav, plus a toast notification sliding in from the top-right (bottom on mobile).
Status tracker: each completed stage on the order tracking timeline lights up (fills with its neon color) with a short animated transition when the page loads, rather than appearing static.
Use Framer Motion on the frontend for all component-level animation; GSAP + ScrollTrigger for complex scroll-linked sequences on the homepage hero, consistent with the approach used on the LTI site.
8.5 Layout & Component Rules
Dark theme only — no light mode toggle; the entire brand identity depends on the dark canvas.
Generous negative space around glowing elements — neon effects need dark space to read as "glowing" rather than just colored.
Rounded corners across cards, buttons, and inputs (consistent radius scale) to match the soft, tube-like quality of neon signage.
Configurator panel: sticky/persistent while scrolling on desktop (side panel), converts to a bottom sheet that can be dragged up/down on mobile.
Sticky cart icon (with live item count) and a sticky WhatsApp/Instagram contact button, both persistent across all pages — these are the two most important conversion actions on the site.
Admin dashboard breaks from the glow-heavy public theme: same dark base and accent colors, but flatter, denser, table-first layouts optimized for fast daily use rather than visual impact.
8.6 Responsiveness
Mobile-first build; every component designed for a narrow viewport first, then expanded for tablet and desktop breakpoints.
Homepage hero: on mobile, simplify any heavy animated/3D elements to lighter-weight versions or static glow images to protect performance and battery.
Product grid: 1 column (mobile) → 2 columns (tablet) → 3–4 columns (desktop).
Configurator: bottom-sheet drawer (mobile) → fixed side panel (desktop), as noted above.
Touch targets on mobile configurator options (color swatches, font choices) sized generously for comfortable tapping.
Test all glow/blur effects on lower-end Android devices during QA — backdrop-blur and heavy box-shadows can be expensive; provide a reduced-effects fallback if frame rates drop.
8.7 Accessibility & Performance Guardrails
Maintain sufficient contrast between neon text/accents and the dark background for readability — glow effects should not compromise legibility of body text or prices.
Respect prefers-reduced-motion — disable flicker/scroll-reveal animations for users who have this OS-level setting enabled.
Lazy-load product images and AI-generated previews; use Cloudinary's automatic format/quality optimization on every image delivered to the frontend.
Keep animation libraries scoped — do not animate every element; motion should draw attention to key actions (add to cart, price updates, status changes), not create constant visual noise.

The AttributeRenderer component is the single most important frontend component in the system: it reads a category's attribute_schema and renders the correct input type for each entry (select, color swatch, image swatch, toggle, slider, text, number). Adding a new attribute type in the admin panel makes it appear on the storefront automatically — no category ever needs bespoke frontend code again.
